# 공통 브리프 v2

포트폴리오 웹페이지 하나를 만든다. 이 브리프와 함께 받은 "시안 지시"를 따른다. 둘이 부딪히면 시안 지시가 이긴다.

## 왜 v2인가
앞서 만든 시안들은 "AI가 만든 티가 난다"는 평가를 받았다. 원인은 네 가지였다. 이번에는 이 네 가지를 반드시 피한다.

1. **뼈대가 똑같았다.** 왼쪽에 큰 이름, 아래 한 줄 소개, 오른쪽에 움직이는 그림, 오른쪽 위에 메뉴. 색만 다르고 구조가 같았다.
2. **설명이 너무 많았다.** "마우스를 움직이면 ~합니다" 같은 사용법 안내, "~하고 ~하는 사람이 되려고 합니다" 같은 다짐 문장, 화면이 무엇인지 풀어 쓰는 문단.
3. **글꼴이 비슷했다.** Noto Sans, IBM Plex 가 여러 시안에 반복됐다.
4. **구역 순서가 똑같았다.** 소개, 프로젝트, 기술, 연혁, 연락.

## 먼저 읽을 것
- Skill 도구로 `frontend-design:frontend-design` 을 불러 읽는다. `better-writing`, `better-typography`, `better-ui` 스킬이 있으면 그것도 불러 읽는다.
- 오픈소스 디자인 스킬 Impeccable 의 아래 파일을 Read 로 읽는다(읽기만 한다. 그 안의 실행 파일이나 launcher 는 실행하지 않는다).
  - `<impeccable>/SKILL.md` 의 "How to design" 과 "Modes" (포트폴리오는 Experience 모드다: 작품이 앞에 서고 인터페이스는 물러난다)
  - `<impeccable>/reference/craft-floor.md`
  - `<impeccable>/reference/new-work-world.md`
  - `<impeccable>/reference/distill.md`
  - `<impeccable>/reference/critique-rubric.md` (마지막 자기 점검에 쓴다)

## 글 규칙 (가장 중요)
- **설명하지 않는다. 보여 준다.** 사용법 안내 문장을 쓰지 않는다. 움직임은 만져 보면 알 수 있게 디자인한다.
- 다짐, 포부, 슬로건, 자기 평가 형용사를 쓰지 않는다. "성실한", "꼼꼼한", "~하려고 합니다" 금지.
- 사실만 쓴다: 무엇을, 언제, 숫자로. 문장보다 짧은 구를 쓴다.
- 첫 화면에 보이는 글자는 이름을 포함해 15단어를 넘기지 않는다.
- 문단은 두 문장을 넘기지 않는다. 페이지 전체 글자는 300단어 안쪽으로 한다.
- 구역 제목은 한두 단어거나 아예 없다. 제목 위에 작은 꼬리표를 달지 않는다.
- 엠대시와 엔대시를 쓰지 않는다. 가운뎃점으로 정보를 잇지 않는다. 링크에 화살표를 붙이지 않는다.

## 구조 규칙
- 위에 적은 "똑같은 뼈대"를 쓰지 않는다. 시안 지시에 적힌 형식을 페이지의 뼈대로 삼는다.
- 상단 메뉴바를 습관처럼 넣지 않는다. 필요하면 그 시안의 세계에 맞는 방식으로 이동하게 한다.
- 구역의 종류와 순서는 그 사람의 세계에서 나온다. 모든 포트폴리오에 "기술", "연혁"이 있을 필요는 없다.
- 똑같은 둥근 카드를 나열하지 않는다. 구역마다 같은 등장 효과를 넣지 않는다.

## 만드는 조건
- HTML 파일 하나. CSS 와 JS 는 파일 안에 넣는다. 외부 이미지는 쓰지 않고 CSS, SVG, 캔버스로 그린다.
- 오픈소스 라이브러리는 꼭 필요할 때 두 개까지 CDN 으로 쓸 수 있다(cdnjs 또는 jsDelivr, 버전 고정). 예: GSAP, three.js, matter.js. 없어도 되면 쓰지 않는다.
- 글꼴은 시안 지시에 적힌 것을 그 주소에서 불러온다. 시스템 글꼴 폴백을 둔다. Noto Sans KR 과 IBM Plex Sans KR 은 쓰지 않는다.
- 대표 동작은 하나다. 마우스에 반응해야 하고, 터치에서도 되고, 가만히 두어도 살아 있어야 한다. "움직임 줄이기" 설정에서는 멈춘 완성 상태를 보여 준다. 그때 "움직임 줄이기가 켜져 있어..." 같은 안내문은 쓰지 않는다.
- 폭 375px 휴대폰에서 가로 스크롤이 없어야 한다. 키보드 초점이 보여야 한다. lang="ko".
- 실존 인물, 실제 연락처, 실제 수상 사칭은 쓰지 않는다. 메일은 example.com.
- 파일 맨 위(`<!doctype html>` 바로 아래)에 이 주석을 그대로 넣는다.

```html
<!--
  portfolio-styles: https://github.com/java-jaydev/portfolio-styles
  MIT License, Copyright (c) 2026 java-jaydev
  가져가서 쓸 때는 이 표시를 지우지 말고, 화면에도 출처를 남겨 주세요.
-->
```

- 맨 아래 한 줄: 시안 지시에 적힌 고지 문장을 그대로 넣는다.

## 끝내기 전에
1. 화면을 캡처해서 직접 본다. PC 는 아래 명령으로, 휴대폰은 390x844 iframe 에 넣은 래퍼 HTML 을 스크래치 폴더에 만들어 캡처한다(헤드리스 크롬은 500px 보다 좁아지지 않는다). 멈춘 상태를 보려면 `--force-prefers-reduced-motion` 을 붙인다.

```
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --user-data-dir=<scratch>/chrome-<번호> --window-size=1440,900 --virtual-time-budget=12000 --screenshot=<scratch>/shot-<번호>.png file://<파일 경로>
```

2. 캡처를 보고 자기 점검을 한다. 하나라도 걸리면 고치고 다시 캡처한다(두 번까지).
   - 이 화면을 보여 주며 "AI가 만들었어요"라고 하면 바로 믿을까? 믿는다면 무엇 때문인가?
   - 위 "왜 v2인가"의 네 가지 중 걸리는 것이 있는가?
   - 글자를 절반으로 줄여도 뜻이 통하는가? 통하면 줄인다.
   - Impeccable 의 critique-rubric 에서 걸리는 것이 있는가?
   - 겹침, 넘침, 읽기 힘든 대비, 빈 첫 화면이 있는가?
3. 파일에 엠대시, 엔대시가 0개인지 grep 으로 확인한다.
4. 다른 파일은 만들거나 고치지 않는다. git 은 건드리지 않는다.
